# PERSUNA: notes for coding agents

- Package manager: **npm**. Node 22 (`.nvmrc`).
- Before finishing any change, run `npm run check && npm run build`.
- Next.js 16: route `params` are Promises; middleware lives in `src/proxy.ts` (exported `proxy`).
- Schema changes: edit `src/db/schema.ts`, then run `npm run db:generate` and commit the new file in `drizzle/`. Never edit generated migrations.
- The training loop goes in `src/lib/skill/engine.ts`. It must stay storage-free and take a `ModelClient`, so it can be tested with the fake in `engine.test.ts`. Persistence goes in the services (`src/lib/skill/service.ts`, `src/lib/jobs/service.ts`, `src/lib/market/service.ts`). Pages, server actions (`src/app/actions/`) and the CLI call services. Don't put logic in pages or scripts.
- Get a model client with `createModelClient()` (`src/lib/models`). It returns the offline mock when no key is set. Keep `src/lib/models/mock.ts` working with any prompt change, because the UI and tests depend on it.
- Pure business rules (publish gate, edit size, pricing, listing requirements, redaction) live in small modules with unit tests. Add to them rather than inlining checks.
- Every state change a person would ask "who did that?" about goes through `audit()` (`src/lib/audit.ts`), inside the same transaction where there is one. Details hold ids and small facts, never job text.
- Payments go through `src/lib/market/service.ts` and `src/lib/payments/`. Never trust a payment from a URL or form: verify with Paystack's API before changing escrow.
- Method vs material: skills, examples and corrections hold method only. Job text stays in `jobs` and is purged after retention. Never copy job text into a skill or a correction.
- All prompts live in `src/lib/skill/prompts.ts`. Model output is always parsed with a Zod schema (`completeJson`).
- Env is read only through `src/env.ts`. Add new variables there, in `.env.example` and in `.railway/railway.ts`; secrets use `preserve()`.
- Deployment is Railway Infrastructure as Code (`.railway/railway.ts`). Do not add `railway.json` or `railway.toml`.
- The repository is public. Never commit `.env`, keys, or real (non-anonymised) meeting content.

Also read `AGENTS.md`: it is generated by `next dev` and points at the bundled Next.js 16 docs.
